# Поток запросов и взаимодействий при заказе такси

## Предварительно

- **Перед каждым запросом к серверу будет происходить аутентификация через Gateway**
- Водитель заходит в приложение
- Ставит статус "Online" и готов к принятию заказов
- User-service - принимает запрос и ставит статус водителя "Online"
- Notification-service - держит вебсокет-соединение со всеми активными водителями
- Фронт - отправляет каждые 5-10 секунд местоположение водителя
- Notification-service - запрос на User-Service с местоположением водителя
- User-service - кэширует статус и локации водителей в Redis
- Водитель заканчивает смену - фронт отправляет статус "Offline"
- User-service - удаляет кэш водителя и ставит статус "Offline"
- Если водитель оборвал Websocket (вышел из приложения) - Notification-Service
делает запрос на User-Service - ставит статус "Offline"

## 1. Статус created (поездка только создана)

- Пользователь выбирает, куда ему нужно доехать и откуда
- Фронт - запрос на Trip-Service с координатами отправления и назначения
- Trip-service - запрашивает OSRM (distance_km, duration_min)
- Trip-service - запрашивает Open-Meteo-API (weather_coefficient)
- Trip-service - запрашивает у User-service свободных водителей
- Trip-service - читает активные тарифы и считает по ним цены
- Trip-service - создаёт поездку со статусом created
- Trip-service - возвращает фронту варианты активных тарифов (со свободными водителями)
и цен с детализацией
- Пользователь выбирает из предложенных вариантов

---
## 2. Статус searching (поиск водителя по тарифу)

- Пользователь выбрал тариф (запрос на Trip-Service)
- Фронт - запрос на Trip-Service с выбором нужного тарифа
- Trip-service - закрепляет цену поездки и выбор тарифа, ставит статус - searching
- Trip-service - выбирает водителя с ближайшей локацией к пользователю
- Водитель принимает или отклоняет заказ (с последующим штрафом)
- Если все водители отказались или по тарифу не осталось свободных водителей - пересоздаем поездку

---
## 3. Статус driver_assigned (водитель назначен)

- Водитель принимает заказ 
- Фронт - запрос на Trip-Service с accept нужной поездки
- Trip-service - обновляет driver_id и устанавливает статус driver_assigned
- Trip-service - запрос на Payment-service с заморозкой средств
- Payment-service - замораживает средства с карты пользователя
- Trip-service - запрос на User-service на смену статуса водителя
- User-service - меняет статус водителя на "Busy" (занят), меняет кэш
- Trip-service - событие RabbitMQ для Notification-service
- Notification-service - отправляет WS-уведомление (Водитель найден и едет)
пассажиру и запись в tasks

---
## 4. Статус in_progress (поездка началась)

- Водитель нажимает "начать поездку" после посадки пассажира
- Фронт - запрос на Trip-Service с start нужной поездки
- Trip-service - обновляет статус поездки на started
- Trip-service - событие RabbitMQ для Notification-service
- Notification-service - отправляет WS-уведомление (Поездка началась)
пассажиру и запись в tasks

---
## 5. Статус completed (поездка завершена)

- Водитель нажимает "завершить поездку" после высадки пассажира
- Фронт - запрос на Trip-Service c complete нужной поездки
- Trip-service - обновляет статус поездки на completed
- Trip-service - запрос на Payment-service со списанием средств
- Payment-service - списывает средства с карты пользователя
- Trip-service - запрос на User-service на смену статуса водителя
- User-service - меняет статус водителя на "Online" (доступен для поездок), меняет кэш
- Trip-service - событие RabbitMQ для Notification-service
- Notification-service - отправляет обеим сторонам WS-уведомление об окончании поездки
и просьбу оценить водителя/пассажира
- Фронт - предлагает выставить оценку обеим сторонам
