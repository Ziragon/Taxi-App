# Поток запросов и взаимодействий при заказе такси

## 1. Статус created (поездка только создана)

- Пользователь выбирает, куда ему нужно доехать и откуда
- Фронт - POST /trips { origin_lat, origin_lng, destination_lat, destination_lng }
- Сервер - запрашивает OSRM (distance_km, duration_min)
- Сервер - запрашивает Open-Meteo-API (weather_coefficient)
- Сервер - считает цены по всем тарифам
- Сервер - создаёт поездку со статусом created
- Сервер - возвращает фронту варианты тарифов и цен с детализацией
- Пользователь выбирает из предложенных вариантов

---
## 2. Статус searching (поиск водителя по тарифу)

- Пользователь выбрал тариф
- Фронт - PATCH /trips/{id} { trip_class: "economy" }
- Сервер - закрепляет цену поездки и выбор тарифа, ставит статус - searching
- Сервер - начинает подбор водителей

---
## 3. Статус driver_assigned (водитель назначен)

- Водитель принимает заказ
- Сервер - обновляет driver_id и устанавливает статус driver_assigned
- Сервер - делаем запрос на оплату и заморозку средств с карты пользователя

---
## 4. Статус in_progress (поездка началась)

- Водитель нажимает "начать поездку" после посадки пассажира
- Фронт - PATCH /trips/{id}/start
- Сервер - ставит статус поездки in_progress

---
## 5. Статус completed (поездка завершена)

- Водитель нажимает "завершить поездку" после высадки пассажира
- Фронт - PATCH /trips/{id}/complete
- Сервер - ставит статус поездки completed
- Сервер - делает списание средств с карты пользователя
- Сервер - сохраняет payment_id в trips
- Фронт - предлагает выставить оценку обеим сторонам
